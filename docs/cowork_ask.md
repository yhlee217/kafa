# Claude 에게 미해소 계정 묻기 — 붙여넣을 프롬프트

위하고도 못 정하고, 이 수임처의 지난 처리 이력으로도 못 정한 행(**미해소**)의 차변계정을
Claude 에게 묻는다. 별도 API 키나 추가 비용은 없다. 이미 쓰고 있는 Claude(Cowork 또는
Claude Code)가 답한다.

## 무엇이 Claude 에게 가나

**업태 · 종목 · 품명 · 유형, 그리고 같은 특징이 몇 건인지뿐이다.** 거래처 이름, 사업자번호,
금액, 날짜, 수임처 이름은 질문지에 **없다**. 코드가 구조적으로 빼고, 품명에 가맹점 이름이나
긴 번호가 섞여 있으면 `(가맹점)` · `#` 으로 가린다(`kafa/recommend/features.py`).

같은 특징은 한 번만 묻는다. 수임처나 달이 바뀌어도 업태·종목·품명·유형이 같으면 같은 답을
쓴다. 업태 표기만 다른 것(`소매업` / `도소매`)은 `config/industry.yaml` 기준으로 한 질문이 된다.

## 흐름

```
kafa-run                     ← 수집 → 속성 → [물을 것 정리] → 분류
   └ 새 질문이 있으면 멈춘다(종료코드 3) — ~/kafa-out/_ai/questions.json
Claude 에게 아래 프롬프트     ← questions.json 을 읽고 answers.json 을 쓴다
kafa-run --skip-fetch        ← 답지를 합치고(picks.json) 분류 — Claude 답이 적용된다
```

- **이력이 먼저다.** 이 수임처가 그 가맹점이나 업종을 처리해 온 방식(시드)으로 풀리는 행에는
  Claude 답을 쓰지 않는다. Claude 는 그것이 못 푼 행에만 쓴다.
- **확신 0.5 미만은 적용하지 않는다.** 그런 행은 미해소로 남고, 리포트 근거 칸에
  `AI(Claude) 메모: …(확신 0.3 — 적용 안 함)` 으로 참고만 남는다. 기준은
  `config/rules.yaml` 의 `recommend.host_picks` 에 있다.
- 적용된 행은 '추천'(판정유형 recommended)이고, 근거는 `AI(Claude) 추정: …`, 신뢰도는 최대 70%다.
  검토 리포트의 추천내역에서 확인한다. 직원 없는 수임처에 복리후생비가 나오면 검토 표시가
  붙고, 접대비면 불공제·유형 일반이 따라붙는다(DED-007). 다른 추천과 같다.
- '모름' 답도 기록한다. 다시 묻지 않고, 담당자가 볼 메모로 남는다.
- 기다리지 않고 진행하려면 `kafa-run --skip-fetch --no-ask` 를 쓴다(질문은 다음에 다시 나온다).

## 먼저 시험부터 (권장)

운영에 붙이기 전에 **이미 처리된 행으로 Claude 정답률을 잰다**. 정답(위하고·담당자가 정한
계정)은 로컬 `exam_key.json` 에만 있고, 시험지는 질문지와 같은 모양이다.

```bash
kafa-ask exam            # ~/kafa-out/_ai/exam_questions.json (기본 150문제)
#   → Claude 에게 아래 프롬프트의 '시험' 판을 붙여넣는다 → exam_answers.json
kafa-ask score           # 정답률 · (제)/(판)만 다름 · 갈리는 업종 · 확신 구간별 정답률 · 틀린 예
```

확신 구간별 정답률을 보고 `min_confidence` 를 정한다. 예를 들어 0.5~0.8 구간 정답률이 낮으면
0.8 로 올린다. 출력에는 수임처·거래처 이름이 없어 그대로 공유해도 된다.

## 환경
- 레포: `/Users/eyonghwi/Dev/Mirrorball/kafa`
- 실행은 레포 폴더에서 `PYTHONPATH=$PWD .venv/bin/python -m kafa.ask_cli ...`
- 질문지: `~/kafa-out/_ai/questions.json`
- 답지(네가 쓴다): `~/kafa-out/_ai/answers.json`

## 절대 규칙
1. **질문지만 연다.** `~/kafa-inbox` 의 엑셀, `~/kafa-out` 의 업로드본·리포트·`kafa.db`·
   `_archive`, `_ai/exam_key.json` 은 열지 않는다. 거기엔 거래처·사업자번호가 있다
   (시험 정답도 있다).
2. 질문지에 없는 정보를 지어내지 않는다. 판단이 서지 않으면 **모름(code: null)** 이다.
   모름은 실패가 아니다. 담당자가 직접 보는 게 맞는 건이다.
3. 계정은 질문지의 `accounts` 에서만 고른다(코드 숫자로). 목록에 없는 계정을 만들지 않는다.

## 할 일
1. 먼저 질문지를 최신으로 만든다:
   `PYTHONPATH=$PWD .venv/bin/python -m kafa.ask_cli prepare`
2. `questions.json` 을 읽는다. `accounts` 는 이 사무실이 실제로 쓴 계정이고 `used` 가 쓴
   횟수다. `(판)` 판매관리비와 `(제)` 제조원가 중 무엇을 쓰는지도 여기서 보인다. 특별한
   근거가 없으면 많이 쓴 쪽을 따른다.
3. 질문마다 `업태 / 종목 / 품명 / 유형` 만 보고 계정을 고른다. `rows` 는 건수다. 많은 것부터
   신중하게 본다.
4. 답지를 JSON 으로 쓴다. 질문이 많으면 50개씩 나눠 생각하되, 파일은 하나다:
   ```json
   {"answers": [
     {"id": "질문의 id 그대로", "code": 830, "confidence": 0.8, "why": "사무용품 도매 — 소모품"},
     {"id": "…", "code": null, "why": "업무무관 의심(약국) — 담당자 판단"}
   ]}
   ```
   - `confidence` 는 0~1, 솔직하게 준다. 0.5 미만은 적용되지 않고 메모로만 남는다.
   - `why` 는 한 줄 근거다. 거래처 이름을 추측해 적지 않는다.
5. 검증한다: `PYTHONPATH=$PWD .venv/bin/python -m kafa.ask_cli apply`
   '받지 않음' 이 있으면 이유(없는 id / 허용되지 않은 계정코드)를 보고 그 줄만 고쳐
   `answers.json` 에 다시 써서 한 번 더 apply 한다.
6. 보고는 **건수만** 한다: "답 120 · 모름 35 · 받지 않음 0, 많이 고른 계정 상위 5개".

## 판단 기준 (담당자 확인 — docs/domain_notes.md)
- 카페·커피: 거의 다 **접대비**.
- 식당 밥값: 직원이 있으면 **복리후생비**. 수임처마다 갈리므로 확신을 0.6 이하로 둔다.
- 식당이 편의점·마트에서 산 것: 상품·**재료비** 쪽. 업태만으로 알 수 없으면 모름.
- 휴대폰·통신 요금: **통신비**.
- 주유·차량 수리: **차량유지비**. 공제 여부는 계정이 아니라 유형이 가르므로 신경 쓰지 않는다.
- 온라인쇼핑: 품명으로 용도가 보이면 그 계정(소모품비 등), 안 보이면 모름.
- **병원·약국·학원·교육·보험·생활용품**: 업무무관일 수 있다. 계정을 고르지 말고
  모름 + why 에 "업무무관 의심" 이라고 적는다. 처리 방식(법인 가수금, 개인 인출금 또는 제외)은
  담당자가 정한다.
- 업태·종목이 결제대행·전자결제처럼 보이면 모름. 실제 가맹점은 다른 흐름으로 되찾는다.

## '시험' 판 (정답률 재기)
위와 같되, 파일만 바꾼다.
- 1번 대신 `PYTHONPATH=$PWD .venv/bin/python -m kafa.ask_cli exam`
- 질문지 → `~/kafa-out/_ai/exam_questions.json`, 답지 → `~/kafa-out/_ai/exam_answers.json`
- 5번 대신 `PYTHONPATH=$PWD .venv/bin/python -m kafa.ask_cli score`. 나온 표를 그대로 보고한다
  (수임처·거래처 이름은 없다).
- `exam_key.json` 은 **절대 열지 않는다.** 정답을 보고 풀면 시험이 의미 없다.
