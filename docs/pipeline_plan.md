# 데이터 파이프라인 구축 계획 (베이스 데이터)

## 시나리오 (확정)
```
① 사람: 필요한 자료를 inbox 디렉토리에 다 내려받기   (ToS 안전 · 수동)
        ↓
② 배치: inbox 체크(일괄)  →  나중에 폴더 감시(상시)로 승급
        ↓
③ (고객별) 정규화 → 분류 → 미추천 해소 → 신고 전 점검
        ↓
④ SQLite 로컬 DB 누적(단일 원본)  +  업로드용 .xls · 리포트 생성
        ↓
⑤ 결과 폴더로 전달  /  처리한 원본은 archive 로 이동
```
위하고 가져오기/내보내기 자동화(RPA·API)는 **약관·인증 확인 후 별도**. 이 토대는
데이터가 어떤 경로로 오든 그대로 재사용된다.

## 원칙
- **로컬 전용**: DB·산출물 모두 사용자 PC. PII(거래처·사업자번호)는 로컬 코드 처리
  범위에서만. **LLM/외부로는 절대 전송 안 함**(리포트는 마스킹).
- **고객별 분리**: dup(중복 방지)·recon(거래처/계정 대사) 기준선을 고객마다 분리.
- **멱등성**: voucher_key(해시) 기준 — 같은 파일을 두 번 넣어도 DB에 중복 적재 안 됨.
- **에러 격리**: 한 파일이 깨져도 나머지는 계속, 실패는 로그로.

## 디렉토리 (런타임, 사용자 PC)
```
<inbox>/<고객>/*.xlsx           ← 위하고 다운로드본(고객별 하위폴더 권장)
<out>/
  <고객>/<기간>/*_upload.xls     ← 업로드용 + _review/_prefile/_bizno/_vat/_risk
  <고객>/_state/dup.json,recon.json
  _archive/<고객>/               ← 처리 끝난 원본 이동
  _logs/manifest.json            ← 실행/실패 기록
  kafa.db                        ← SQLite 단일 원본(거래 누적)
```

## 구성요소
- `kafa/store/` — SQLite 저장소(VoucherStore): 고객·기간별 거래 누적, voucher_key upsert(멱등).
- `kafa/pipeline/` — inbox 일괄 처리(runner) + CLI(`kafa-pipeline`).
- 분류·추천·리포트는 **기존 엔진 재사용**(process_rows).

## 고객 식별
- 현재: **고객별 하위폴더**(폴더명 = 고객ID). 단순·안전.
- 추후(샘플 확보 시): 파일 내용(사업자번호/상호)으로 자동 라우팅 추가 가능.

## 단계
- **Phase 1 (지금)**: 일괄 처리 + SQLite 누적 + 고객별 상태 + 아카이브 + CLI + 테스트.
- **Phase 2**: 폴더 감시(상시 자동) + Windows 시작 시 실행 + 단일 .exe(트레이).
- **Phase 3**: 완료/검토 알림 + 일일 요약(고객 진행 현황 보드).
- **Phase 4**: 재시도·모니터링·백업(외장/NAS, 클라우드 X).
- **Phase 5 (선택, 약관 확인 후)**: 위하고 가져오기/내보내기 자동화(공식 API 우선, 없으면 감독형 RPA).
