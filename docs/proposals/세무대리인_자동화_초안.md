# 세무대리인 반복업무 자동화 — 프로젝트 발의 초안 5건

세무대리인(기장 대리)이 **매달 반복**하고 **시간이 많이 드는** 업무를 골라 프로젝트로
발의한다. 각 초안은 "데이터 없이도 안전하게 지금 만들 수 있는 부분"을 **이미 구현**해
두고(코드+테스트), 나머지(실데이터·외부 API 필요)는 보류로 명시했다.

> 읽는 법: 각 초안은 **As-Is(지금 어떻게 하나)** → **To-Be(자동화하면)** →
> **이번에 구현한 것** → **보류** → **써보기** 순서다. 코드는 `kafa/agent/` 에 있다.

## 한눈에 보기

| # | 초안 | 핵심 업무 | 반복성/소요 | 이번 구현 | 모듈 |
|---|---|---|---|---|---|
| 1 | 신고 전 자가검증 | 부가세 신고 직전 오류 점검 | 신고철마다·실수 잦음 | ✅ 코어 | `agent/prefile_check.py` |
| 2 | 사업자번호 일괄검증 | 거래처 번호 유효성·휴폐업 확인 | 매월·건건 조회 | ✅ 코어(조회 보류) | `agent/bizno_batch.py` |
| 3 | 원천징수 계산 | 프리랜서·기타소득 세액 계산 | 지급 건건·매월 | ✅ 코어 | `agent/withholding.py` |
| 4 | 자료 수취 관리 | 월 자료 요청·누락 독촉 | 매월·고객마다 | ✅ 코어 | `agent/intake.py` |
| 5 | 거래처/계정 대사 | 신규 거래처·분류 일관성 점검 | 매월 | ✅ 코어 | `agent/recon.py` |

테스트 11건 추가(합성·비-PII), 전체 163건 통과.

## 초안 1 — 부가세 신고 전 자가검증 체크리스트

**한 줄**: 신고 버튼 누르기 전, 흔한 오류를 자동으로 한 번 훑어 준다.

- **As-Is**: 신고 직전 담당자가 엑셀을 눈으로 보며 합계가 맞는지, 불공제를 빠뜨리지
  않았는지, 사업자번호가 이상하지 않은지, 부가율이 튀지 않는지, 중복은 없는지 수기로
  점검. 신고철마다 반복되고 사람이 하니 실수가 난다.
- **To-Be**: 분류 결과를 넣으면 5개 항목을 **PASS/WARN 체크리스트**로 자동 출력. ⚠️ 가
  하나도 없으면 "신고 준비 완료". 어디를 더 봐야 하는지 건수로 짚어 준다.
- **이번 구현**: `build_prefile_check(rows)` → ① 합계 검산(공급가액+세액+비과세=합계)
  ② 공제/불공제/검토 정합(검토 잔여 0인지) ③ 사업자번호 체크섬 ④ 부가율 이상 ⑤ 중복.
  기존 `validate.py` 재사용. 출력은 **건수만**(PII 없음).
- **보류**: 매출 측 집계와의 교차검증(매출 데이터 필요), 업종별 부가율 기준선 정교화.
- **써보기**:
  ```python
  from kafa.agent.prefile_check import build_prefile_check, render_prefile_check
  print(render_prefile_check(build_prefile_check(classified_rows)))
  ```

## 초안 2 — 사업자등록번호 일괄검증 + 홈택스 조회목록

**한 줄**: 거래처 번호를 한 번에 정리해, 명백한 오류를 거르고 조회할 것만 추린다.

- **As-Is**: 거래처 사업자번호의 유효성·휴폐업을 홈택스에서 **건건이** 조회. 거래처가
  많으면 시간 소모가 크고, 중복·오타 번호까지 일일이 본다.
- **To-Be**: 번호 목록을 넣으면 ① 중복 제거 ② 체크섬으로 **형식 오류를 먼저 선별** →
  실제 조회해야 할 "유효·중복제거" 목록만 남긴다. 조회 건수 자체를 줄여 준다.
- **이번 구현**: `check_biznos([...])` → 입력/중복/유효/오류 집계 + 조회 대상 목록.
  요약 출력은 마스킹(`123-**-*****`), 조회용 원문은 로컬 보관(LLM·외부 미전달).
- **보류**: 실제 홈택스 **상태조회(휴폐업·유효성)** — 공동인증/Open API 필요. 조회
  결과 캐싱·갱신 주기.
- **써보기**:
  ```python
  from kafa.agent.bizno_batch import check_biznos, render_bizno_summary
  res = check_biznos(거래처_사업자번호_목록)      # 원문은 로컬에만
  print(render_bizno_summary(res))                # 마스킹 요약
  ```

## 초안 3 — 원천징수세액 계산 보조

**한 줄**: 프리랜서·기타소득 지급 때 세액을 유형별로 자동 계산한다.

- **As-Is**: 인적용역·강사료·기타소득 지급마다 소득세(3% 또는 8%)와 지방소득세(소득세의
  10%)를 계산기로 두드리고 지급명세서를 만든다. 지급 건건·매월 반복.
- **To-Be**: (지급액, 유형) 목록을 넣으면 **소득세·지방소득세·실지급액 계산표**를 자동
  생성. 소액부징수 대상은 플래그로 표시.
- **이번 구현**: `compute_withholding(지급액, "사업소득")`, `compute_batch([...])`.
  율은 `config/agent.yaml` 외부화(사업소득 3.3%, 기타소득 8.8%), 원 단위 절사,
  소득세<1,000원이면 `소액부징수_검토=True`. 금액만 처리(수령자 PII 없음).
- **보류**: 비거주자·감면·필요경비율 변동·4대보험 연동·소액부징수 적용범위 확정,
  지급명세서 양식 출력(국세청 서식 확보 후).
- **써보기**:
  ```python
  from kafa.agent.withholding import compute_batch, render_withholding
  print(render_withholding(compute_batch([(1_000_000, "사업소득"),
                                          (500_000, "기타소득")])))
  ```

## 초안 4 — 월별 자료 수취 체크리스트 + 요청 메시지

**한 줄**: 매달 고객별로 받을 자료를 체크리스트로 만들고, 빠진 것만 콕 집어 요청 문구를 뽑는다.

- **As-Is**: 매달 고객마다 카드내역·세금계산서·통장 등 자료를 요청하고, 빠진 자료를
  찾아 독촉 메시지를 일일이 작성. 고객 수만큼 반복되는 커뮤니케이션.
- **To-Be**: 고객·월·"받은 자료"를 넣으면 **수취/누락 체크리스트**와 누락분만 담은
  **요청 메시지 초안**을 자동 생성. 담당자는 검토 후 발송만.
- **이번 구현**: `build_intake_checklist(period, client, received_types)`,
  `draft_request_message(...)`. 자료유형 목록은 `config/agent.yaml`. 고객명 마스킹.
  (메시지 문구 품질을 더 올리려면 `kafa.loop` 의 `guide` 스펙으로 다듬기 루프 적용 가능.)
- **보류**: 받은 파일 자동 인식(파일명/포맷 규칙 확정 필요), 메신저/메일 발송 연동.
- **써보기**:
  ```python
  from kafa.agent.intake import build_intake_checklist, draft_request_message
  c = build_intake_checklist("2026-03", "행복상사", ["신용카드 매입내역", "통장 거래내역"])
  print(draft_request_message(c))
  ```

## 초안 5 — 전월 대비 거래처/계정 변동 대사

**한 줄**: 이번 달에 새로 나타난 거래처와, 같은 거래처인데 계정이 달라진 건을 자동으로 짚어 준다.

- **As-Is**: 매월 신규 거래처가 생겼는지, 같은 거래처를 지난달과 다른 계정으로
  분류하지 않았는지(일관성)를 수기로 비교. 거래가 많을수록 놓치기 쉽다.
- **To-Be**: 이번 달 분류 결과를 **직전 기준선과 대사**해 ① 신규 거래처 ② 계정 변동을
  자동 플래그. 기준선은 **거래처를 해시로만** 보존(실명 미보존 — PII 안전).
- **이번 구현**: `reconcile(rows, baseline)` → (신규/변동 결과, 갱신된 기준선).
  `VendorBaseline` 로 로컬 JSON 보존(해시→계정코드). 출력 거래처는 마스킹.
- **보류**: 계정 변동의 "정상/이상" 자동 판단(업종·정책 맥락 필요 → 플래그까지만),
  매출 거래처까지 확장.
- **써보기**:
  ```python
  from kafa.agent.recon import reconcile, render_recon, VendorBaseline
  vb = VendorBaseline("vendor_base.json")
  res, new_base = reconcile(classified_rows, vb.mapping)
  print(render_recon(res)); vb.save(new_base)
  ```

## 공통 원칙 (모든 초안 유지)

- **보안 제0원칙**: 원천 PII(거래처 실명·사업자번호·수령자 정보)는 로컬 코드만 처리.
  외부 노출(요약·리포트·로그)은 **마스킹/해시/합계만**. 모델/서브에이전트로 안 보낸다.
- **추측 금지**: 데이터·서식·API 가 있어야 확정되는 부분은 값을 박지 않고 **보류/플래그**.
- **외부화**: 율·한도·목록은 `config/agent.yaml`. 코드 하드코딩 금지.
