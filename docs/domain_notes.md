# 실무 도메인 메모 (담당자 구두 확인)

담당자(세무 실무자)와 실제 자료를 함께 보며 확인한 내용. **전사(轉寫) 기반이라
숫자·용어는 재확인 대상**이며, 코드 반영 시에는 config 로 두고 검토 플래그를 남긴다.

---

## 1. 신용카드 매입은 **두 번** 업로드된다 (2026-08-07 확인)

```
신용카드 자료
   ├─ ① 부가세 공제 대상 → 부가세 신고 때 이미 반영됨(매입세액공제)
   └─ ② 나머지(공제 안 된 것·미추천 등) → **일반전표로 다시 업로드**
                                          (소득세/법인세 신고용)
```

- 부가세 신고분을 **뺀 나머지**가 일반전표로 들어간다.
- 현재 kafa 는 ①(신용카드 매입 업로드)만 만든다. **②는 미구현** → 별도 과제.
- 담당자 요청: "올리는 것까지 자동화". 단 **업로드 전 사람이 확인**하는 절차는 유지.

## 2. 미추천이 접대비로 가는 이유 (핵심)

담당자 설명 그대로:
- **직원이 없으면 복리후생비가 성립하지 않는다.** 1인 사업자 등은 복리후생비 계정 자체가
  의미 없음 → 마트·편의점·식사·커피 같은 소액이 **접대비로** 간다.
- **간이과세자 등 어차피 공제가 안 되는 건**도 접대비로 넣어왔다.
- 그래서 기존 이력이 "접대비" 위주인 수임처가 생긴다.

→ 즉 "음식점 = 접대비/복리후생비" 는 업종이 아니라 **수임처 속성(직원 유무 등)** 이 가른다.
→ 기존에 세운 가설("수임처마다 다르다")과 일치하며, **왜 다른지**까지 확인됨.

## 3. 개인 vs 법인 처리가 근본적으로 다르다

| | 법인 | 개인 |
|---|---|---|
| 카드 부채 | **미지급비용으로 반드시 계상** — 다음 달 통장 인출과 금액을 맞춰야 함 | 상대계정 불필요 |
| 업무무관 건 | 빼면 통장이 안 맞음 → **전부 반영** | **삭제해버린다**(의료비·집 살림 등) |
| 업로드 범위 | 카드 사용분 전부 | 업무용으로 인정할 것만 |

→ 현재 kafa 는 **모든 행을 업로드**하는 구조. 개인 수임처의 '제외' 처리는 미구현.

## 4. 업종별 성격 차이 (사례)

- **서비스업(영상제작 등)**: 매입 원가가 있어 웬만한 건 부가세 공제 가능. 프로젝트가
  해외·제주·부산 등으로 옮겨 다녀 **거래처가 매우 많고 반복이 적다**.
- **건설/인테리어(매출 ~50억)**: 현장이 많아 법인카드 사용량·거래처 수가 매우 많다.
- → 수임처에 따라 "처음 보는 가맹점" 비율이 크게 다르다. 이력 기반 추천의 효과도 다르다.

## 5. 과거 이력이 항상 옳지는 않다

- 실사례: 교회(강남 소재)에 **주차**했다는 이유로 `차량유지비`로 처리된 5,500원 건.
- → 이력 학습은 강력하지만 **오분류도 함께 학습**한다. 검토 플래그를 없애면 안 된다.

## 6. 수집 타이밍·결측 (수집 자동화 설계에 반영)

- 카드 자료는 **매월 15일경**에 나온다 → 8월 초에는 7월분이 아직 없다.
- **조회 자체가 안 되는 수임처**가 있다:
  - 카드가 등록되지 않은 곳
  - 홈택스 계정 정보 미등록
  - **폐업한 곳**(예: 2025-12-31 까지만 영업)
- → 수집기는 "데이터 없음"을 **실패가 아니라 정상**으로 구분해야 한다.

## 7. 오래된 수임처일수록 이력이 강력하다

- 20년 이상 거래한 곳이 많고, 사업장 위치가 잘 안 바뀌므로 **쓰던 곳에서 계속 쓴다**.
- 담당자가 처리해 온 기록이 그대로 정답 역할을 한다 → **과거 자료를 최대한 끌어오는 것**이
  추천 정확도에 직결(실측: 이력 있으면 96%).

---

## 재확인 필요 (전사 기반이라 확정 금지)

1. 일반전표 업로드의 **정확한 양식·필수 컬럼**(신용카드 매입 양식과 다름)
2. 개인 수임처에서 **제외 기준**(무엇을 빼는지) — 의료비·가사 등, 판단 주체는 담당자
3. "직원 없음"을 시스템이 어떻게 아는가 — 수임처 속성으로 **수기 입력** 필요
4. 간이과세자 판별 방법(다운로드본에 식별자 없음 — 여전히 미해결)


## 위하고 신용카드 화면 — 엑셀 내려받기 위치 (담당자 확인 2026-08-30)
'엑셀변환' 은 툴바 버튼이 아니라 **조회 결과 표의 데이터 행에서 우클릭**했을 때 나오는
메뉴 안에 있다. 표 자체는 canvas 로 그려져 있어(`div#GRID_TOP` 안) 행을 DOM 으로 집을 수
없다. 그래서 표 영역에 우클릭 → 뜬 메뉴에서 '엑셀변환' 을 누른다.
데이터가 없으면 메뉴가 뜨지 않으므로 **조회를 먼저** 해야 한다.
selector 는 `config/fetch/wehago.yaml` 의 `excel_context_target` / `excel_download_button`.


## 신용카드 화면의 조회 구분 (2026-08-30 확인)
수임처를 새로 열면 조회 구분이 **매출**로 시작한다. 그대로 조회하면
'조회조건에 맞는 데이터가 없습니다' 팝업이 뜬다(매입 자료만 다루므로 결과가 없다).
그래서 수집 전에 구분을 **'2. 매입'** 으로 바꿔야 한다.

화면에 비슷한 드롭다운이 3개(모두 '리스트 열기')라 class 로 집으면 접혀 있는 것을
먼저 잡아 멈춘다. **현재 값 글자('1. 매출')를 눌러** 목록을 여는 방식이 확실하다.
잘못 잡았을 때의 안전장치는 받은 파일 이름에 '매입' 이 있는지 확인하는 것이다.
설정: `config/fetch/wehago.yaml` 의 `kind_*` 항목.


## 수임처를 여는 길 — 주소가 먼저 (2026-08-30 확인)
수임처 마스터에는 수임처마다 **완전한 접속 주소**가 들어 있다. 그 주소로 바로 가면
목록 검색·'회계' 클릭·'신용카드' 클릭이 전부 필요 없다. (주소에 cd_com·gisu·companyID
같은 수임처별 값이 섞여 있어 **cno 만 바꾼 틀**은 만들 수 없지만, 각자의 주소는 그대로
쓸 수 있다.) 주소가 없거나 안 통하는 곳만 아래 목록 경로로 되돌아간다.

회계 첫 화면이 뜨는 경우에는 **'신용카드' 를 한 번 더** 눌러야 조회 화면이 나온다.

## 수임처 목록에서 회계로 들어가기 (2026-08-30 확인)
수임처 **이름 링크를 누르면 수임처 정보 화면**으로 간다. 회계로 들어가려면 그 수임처
행에 있는 **'회계' 버튼**을 눌러야 한다. 행을 CSS 로 집기 어려워, 이름 링크
(`a#tooltip_<수임처코드>`)에서 부모로 올라가며 같은 행 안의 '회계' 버튼을 찾는다.
위로 올라가다 처음 만나는 것이 그 행의 버튼이라 다른 수임처를 여는 사고가 없다.
설정: `config/fetch/wehago.yaml` 의 `client_open_button_text`(비우면 예전 방식).

## '조회조건에 맞는 데이터가 없습니다' 팝업 (2026-09-02)
자료가 없으면 **알림창**으로 뜬다. 화면 본문 글자가 아니라 팝업이라, 완전일치
(`text="..."`)로 찾으면 마침표 하나만 달라도 놓친다 — 실제로 자료 없는 곳이
'자료 있음' 으로 잡혔다. 그래서 **보이는 알림창**(`.WSC_LUXConfirm`, `.dialog_alert` 등)
안의 글자에 문구 **조각**이 들어 있는지로 본다(`empty_result_texts` 는 짧은 조각으로 적는다).
비교할 때 **띄어쓰기·줄바꿈을 모두 지운다** — 실제 문구가 '조회 조건' 처럼 띄어쓰기가
들어가 있어 조각을 그대로 비교하면 놓친다. **크기만으로 보이는지 판단하면 안 된다** — `visibility:hidden` 인 요소도 자리를
차지해서, 숨어 있는 안내문을 팝업으로 오인해 전표가 132건 있는 곳까지 '자료 없음' 이
됐다(실측 2026-09-02). `checkVisibility()`(없으면 computed style 을 조상까지 확인)로
진짜 보이는 것만 본다. 화면 글자 전체를 훑는 방식은 숨은 글자까지 걸려 쓰지 않는다.

그리고 **조회 전에 이미 보이던 문구는 팝업이 아니다.** 조회 직전 값을 기억해 두고
달라졌을 때만 '자료 없음' 으로 본다(상시 안내문 구분).

실제 문구(2026-09-02):
> 조회 조건에 맞는 데이터가 없습니다.
> 메뉴 상단 [수집하러가기] 버튼을 클릭하여 자동 전표를 수집하거나
> 수집한 기간에 맞춰 조회 조건을 다시 설정해 주시기 바랍니다.
팝업이 늦게 뜨는 곳이 있어 `empty_wait_seconds`(기본 4초) 동안 지켜본다.

## 수임처마다 자료가 없는 경우가 있다
카드 거래가 없는 기수·달이 있어 '조회조건에 맞는 데이터가 없습니다' 팝업이 뜬다.
실패가 아니라 **자료 없음**으로 센다. 전체를 한 번 돌며 어디에 자료가 있고 어디서
막히는지 먼저 파악하려면 `kafa-fetch --probe` (받지 않고 점검만).


## 화면 사진으로 예외 찾기
DOM 만으로는 예상 못 한 화면(점검 공지·권한 안내·처음 보는 팝업)을 알 수 없다.
`--shots` 로 수임처마다 사진을 남기고 사람/AI 가 훑어 예외를 찾는다.
사진은 **거래 내역 표와 거래처 이름을 흐리게** 한 뒤 찍는다(`shot_mask_selectors`).
파일 이름에는 번호와 결과만 넣고, 번호↔수임처 대응표는 `index.csv` 에만 둔다.
가리지 않은 원본이 필요하면 `--shots-raw` 를 명시해야 하며 사람이 눈으로만 본다.


## 사업자 전환 확인 (2026-08-31)
위하고는 화면 안에서 **사업자(수임처)를 전환**하는 방식이다. 전환이 안 되면 이전 수임처
화면이 그대로 남는다. 그걸 모르고 받으면 **남의 자료를 이 수임처 이름으로 저장**하게 된다.
그래서 이동 후 화면이 그 수임처가 맞는지 반드시 확인한다 —
탭 제목이 `신용카드(2기) - (주)○○` 형태라 회사명이 들어 있다(`client_name_display`
를 지정하면 그 요소의 글자를 대신 본다). 비교는 띄어쓰기와 (주)·㈜ 같은 표기 차이를
무시한다. 다르면 목록에서 다시 열고, 그래도 다르면 **받지 않고 실패**시킨다.

또 주소가 `#/...` 해시만 다르면 SPA 가 재로딩하지 않아 화면이 안 바뀐다.
그래서 빈 페이지를 한 번 거쳐 항상 새로 읽게 한다(`hard_navigate`).
실측(2026-09-02) `hard_navigate: false` 로 돌리면 **주소만 바뀌고 화면은 이전 수임처
그대로**였다 — 검증이 이를 잡아냈다.

전환이 안 됐을 때는 ① **새로고침** → ② 그래도 아니면 **목록에서 다시 열기** 순으로
물러선다. 주소로만 다니면 목록 탭이 없으므로, 목록으로 갈 때는 `dashboard_url` 로
먼저 이동한다.
