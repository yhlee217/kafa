# 로드맵 — 세무대리인 고객 서비스 관점

kafa의 방향: **세무대리인(기장 대리)이 고객에게 제공해야 하는 서비스**를 자동화/보조한다.
"신용카드 매입 전표 분류"는 그 서비스의 **첫 모듈**일 뿐이고, 같은 분류 데이터 위에서
기장 → 신고 → 점검 → 고객 보고로 확장한다.

## 세무대리인이 고객에게 제공하는 서비스 (지도)
1. **기장(장부 작성)** — 매입/매출 거래 분류·전표 작성. → 현재 kafa의 핵심.
2. **부가가치세 신고 보조** — 매입/매출 집계, 매입세액공제, 불공제, 면세, 의제매입 대상.
3. **증빙·리스크 점검** — 적격증빙 여부, 미등록/가공 의심, 부가율 이상, 중복.
4. **고객 보고** — 매월/분기 고객에게 주는 한국어 요약(무엇이 처리됐고 무엇을 확인해야 하나).
5. **(데이터 필요)** 매출(세금계산서/계산서/현금영수증), 원천세, 결산/소득세·법인세.

## 모듈 상태
| 모듈 | 서비스 | 상태 | 데이터 필요? |
|---|---|---|---|
| 신용카드 매입 분류·업로드 | 기장 | ✅ 동작 | 아니오(합성으로 검증) |
| 부가세 신고 보조 집계(`report/vat_summary.py`) | 부가세 신고 | ✅ 1차 | 아니오(분류결과 합산) |
| 증빙·리스크 점검(`report/evidence_check.py`) + 검토 리포트 | 증빙·리스크 점검 | ✅ 동작 | 아니오 |
| 정확도 검증(수작업 대조) | 품질 보증 | ✅ 동작 | 정답 CSV(담당자) |
| 고객 제공용 요약 리포트(`report/client_report.py`) | 고객 보고 | ✅ 1차 | 아니오(마스킹 요약) |
| 매출 전표(세금계산서/카드/현금영수증) | 기장·부가세 | ⏸️ 골격 | **예**(양식 샘플) |
| 원천세/급여, 결산/소득세·법인세 | 신고 | ⏸️ 미착수 | **예**(별도 데이터) |

### 세무대리인 반복업무 자동화(`kafa/agent/`) — 발의 5건 (코어 구현)
발의·As-Is/To-Be·보류: `docs/proposals/세무대리인_자동화_초안.md`.

| 모듈 | 업무 | 상태(결선) | 보류(데이터/서식/API) |
|---|---|---|---|
| `prefile_check` | 부가세 신고 전 자가검증 체크리스트 | ✅ 변환 산출물 `_prefile.txt` | 매출 교차검증 |
| `bizno_batch` | 사업자번호 일괄검증 + 조회목록 | ✅ 변환 산출물 `_bizno.txt` | 홈택스 상태조회 |
| `withholding` | 원천징수세액 계산 | ✅ MCP 도구 `withholding` | 지급명세서 서식·예외율 |
| `intake` | 월 자료 수취 체크리스트·요청문구 | ✅ MCP 도구 `intake` | 파일 자동인식·발송연동 |
| `recon` | 전월 대비 거래처/계정 대사 | ✅ 산출물 `_recon.txt`(`--recon-store`) | 변동 정상/이상 자동판단 |

> `kafa/loop/`(Actor↔Evaluator)는 개발/품질용 도구로, 생성 산출물에는 결선하지 않음(의도).

## 확장 우선순위 (데이터 없이 안전하게 가능한 것부터)
1. **부가세 신고 보조 집계** — 분류결과 합산(과세공제/불공제/면세/의제/검토). ✅ 1차 완료.
2. ~~**고객 제공용 요약 리포트**~~ ✅ 완료 — `report/client_report.py`(처리현황+부가세관점+
   고객 확인 요청, 거래처 마스킹·날짜/금액으로 식별).
3. ~~**증빙·리스크 점검 강화**~~ ✅ 완료 — `report/evidence_check.py`(적격증빙 구분 + 불공제/
   검토/미등록 의심/부가율 이상/중복을 거래별 점검표로).
4. ~~**부가세 신고용 산출물 포맷(CSV)**~~ ✅ 완료 — `write_vat_summary_csv`(구분/건수/공급가액/세액).
5. (데이터 확보 후) 매출/세금계산서 처리, 의제매입 율·한도, 개인사업자 상대계정, 카면 등.

## 불변 원칙 (확장해도 유지)
- 보안 제0원칙: 원천 PII는 로컬 코드만. 모델/외부 노출은 마스킹·비-PII·합계만.
- 보류 항목(실데이터 필요)은 추측 확정 금지 — 골격/플래그/검토만.
- 율·한도 등 사업자/기간 변수 계산은 전표 단계에서 하지 않고 신고 단계로 이관(플래그/집계만).
- 변경은 PR로(사람이 검토·병합). 규칙·코드표는 `config/*.yaml` 외부화.
