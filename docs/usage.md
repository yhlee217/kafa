# kafa 사용법 — 쉽게 따라 하기

위하고 '신용카드' 화면에서 내려받은 엑셀(.xlsx)을 **위하고 업로드용 파일(.xls)**로 바꿔 줍니다.

**좋은 점**
- 어려운 명령어가 없습니다. **Claude Desktop(또는 Claude Code)에 말로 부탁**하면 됩니다.
- **추가 비용이 없습니다.** 이미 쓰고 계신 Claude 가 직접 처리합니다(별도 키·추가 요금 없음).
- 계정을 못 정한 '미추천' 건은 **Claude 가 업종·품명을 보고 대신 추천**하고 그 이유도 적어 줍니다.
- 사업자번호·거래처 이름 같은 **민감정보는 절대 밖으로 나가지 않습니다**(컴퓨터 안에서만 처리).

---

## 처음 한 번만: 연결 설정

1) 설치 (검은 화면[터미널]에 한 줄 입력):
```
pip install -e ".[mcp]"
```
2) Claude Desktop 설정 파일에 아래 내용을 넣고, Claude Desktop 을 껐다 켭니다.
   - 설정 파일 위치
     - 맥(Mac): `~/Library/Application Support/Claude/claude_desktop_config.json`
     - 윈도우: `%APPDATA%\Claude\claude_desktop_config.json`
```json
{
  "mcpServers": {
    "kafa": { "command": "kafa-mcp" }
  }
}
```
> 이 설정은 처음 한 번만 하면 됩니다. (Claude Code 를 쓰셔도 같은 방식으로 연결됩니다.)

---

## 매번: 이렇게 말하면 끝

Claude Desktop 대화창에 **파일 위치를 알려주며** 이렇게 말하세요:

> "바탕화면 `카드` 폴더의 `3월.xlsx` 를 변환해서 같은 폴더의 `출력` 에 넣어줘."

그러면 Claude 가 알아서:
1. 파일을 살펴보고(미추천 건이 있으면 업종·품명을 보고 **계정을 추천**),
2. 위하고 업로드용 `3월_upload.xls` 를 만들고,
3. 한국어로 결과를 알려 줍니다. 예:
   > "끝났습니다. `출력` 폴더에 **3월_upload.xls** 를 만들었어요(120건).
   > 그중 **5건은 확인이 필요**합니다 — `3월_review.txt` 에 적어 두었어요.
   > 이 파일을 위하고 '신용카드 매입 엑셀 업로드'에 올리시면 됩니다."

**점검만 먼저** 하고 싶으면: "그 파일 먼저 살펴봐줘" → 건수·미추천 수만 보여 줍니다.

---

## 결과 파일 (출력 폴더에 생깁니다)
| 파일 | 무엇 |
|---|---|
| `*_upload.xls` | **위하고에 올릴 파일** (너무 크면 `_part01.xls`로 나뉨) |
| `*_review.txt` | **확인이 필요한 건** 요약(미추천·검토·이상 거래처) |
| `*_review.csv` | 건별 분류 내역과 **추천 이유**(꼼꼼히 대조하실 때) |

## 막힐 때
- "위하고 파일이 아니라고 나와요" → 위하고 '신용카드' 화면에서 받은 .xlsx 가 맞는지 확인하세요.
- 빨간/검토 표시가 있는 건은 **사람이 한 번 봐야 하는 항목**입니다(예: 주유소=비영업용 의심).

## (참고) 명령어로 쓰기 — 자동화/일괄용
Claude 없이 컴퓨터가 알아서 돌리는 방식입니다. 이때 미추천 추천은 컴퓨터 안의 규칙으로만 합니다.
```
python -m kafa.cli <입력폴더|파일.xlsx> <출력폴더> [--client-type corporate|individual] [--truth 정답.csv]
```

## (참고·선택) 별도 API 로 추정하기
기본은 위처럼 **이미 켜진 Claude** 가 추정하므로 추가 비용이 없습니다. 자동 배치에서 사람이
개입하지 않고 AI 추정을 쓰고 싶을 때만, `config/rules.yaml` 의 `recommend.llm.enabled: true`
로 켜고 환경변수 `ANTHROPIC_API_KEY` 를 설정합니다(이 경우에만 별도 토큰 비용 발생).

## 보장
- **오차 없음/고정 양식**: 변환·코드화는 컴퓨터의 정해진 규칙이 수행하고, 출력은 고정 양식으로만.
- **추가 비용 없음**: 미추천 추천은 이미 쓰고 계신 Claude 가 수행(별도 키 불필요).
- **보안**: 거래처 이름·사업자번호는 AI 에 전달하지 않음(업종/품명/유형만 사용).

## 이미 처리한 파일을 다시 돌릴 때 (주의)

`_archive` 의 원본을 다시 inbox 에 넣고 돌리면 **업로드본이 비어서 나온다.**
2차 중복 가드가 1차 실행 때 모든 키를 `<출력폴더>/<수임처>/_state/dup.json` 에
기억해 뒀기 때문에, 같은 행이 전부 `dup_guard(2차)` 로 걸린다.

재처리하려면 그 기억을 먼저 비운다(DB 는 그대로 둔다 — 누적 이력이 추천의 재료다):

```bash
cp ~/kafa-out/kafa.db ~/kafa-out/kafa.db.bak            # 먼저 백업
find ~/kafa-out -name dup.json -path '*/_state/*' -delete
```

DB 는 `INSERT OR IGNORE` 라 재적재해도 늘지 않는다. 새로 들어오는 건
**예전에 키 충돌로 못 들어갔던 행**뿐이다(2026-09-06 수정 — docs/domain_notes.md).

### 빠져 있던 전표만 보충 업로드 (2026-09-06 수정의 뒤처리)
이미 업로드를 마쳤다면 전체를 다시 올리면 안 된다 — 이중계상이 된다.

```bash
python tools/check_dupkeys.py ~/kafa-out/_archive          # 몇 건인지 (읽기 전용)
python tools/extra_upload.py ~/kafa-out/_archive ~/kafa-보충 --db ~/kafa-out/kafa.db
```

`~/kafa-보충/<수임처>/…_보충_upload.xls` 만 추가로 올린다. 둘 다 읽기 전용이라
DB 도 dup.json 도 건드리지 않는다.

계정이 비어 있는(미해소) 행을 빼고 만들려면 `--skip-unresolved` 를 준다. 뺀 행은
**사라지지 않고** `미해소_수기입력.csv` 로 나오므로 위하고에 직접 넣으면 된다.
(조용히 사라지는 것이야말로 이 수정이 잡으려던 문제다 — 절대 그냥 버리지 않는다.)

뺀 건들을 눈으로 보려면:

```bash
python tools/show_unresolved.py ~/kafa-보충/미해소_수기입력.csv
```

거래처 실명은 **그 화면에만** 나온다. 아래쪽에 실명 없는 요약(업태·종목·품명·건수)이
따로 찍히므로, 계정을 상의할 때는 그 요약만 옮긴다 — 추천 엔진도 같은 특징만 쓴다.

## 행 수·금액 대사 — `대사 OK` 가 아니면 올리지 마세요

파일마다 이렇게 한 줄이 찍힙니다.

```
[고객A/2026-03] 3월.xlsx → 작성 4/스킵 0 (DB 신규 4/기존 0)
    대사 OK — 입력 4 = 업로드 4 + 스킵 0
[실패] 고객B/3월.xlsx → IntegrityError: 대사 불일치 — … 파일 하단 총계 3건인데 읽은 행은 2건
```

- **대사 불일치**면 그 파일은 실패로 끝나고(종료코드 1), 업로드본은 만들지 않거나
  이름 끝에 `.대사불일치` 를 붙여 보류합니다. 위하고 업로드 창에 뜨지 않습니다.
- 어디가 안 맞는지는 `<파일>_upload_대사.txt` 에 있습니다(건수·금액·스킵 사유).
- 원본은 inbox 에 그대로 남습니다. 원인을 고친 뒤 다시 돌리면 됩니다.
- **이미 올린 달은 다시 돌리지 마세요** — 2026-10 수정 이후로는 같은 날 반복 결제가
  업로드본에 들어가므로, 보충본까지 올린 달을 다시 돌리면 이중계상이 됩니다.

## 공제 기준 점검 — '유형' 칸이 담당자가 고른 결과인가 (읽기 전용)

담당자는 공제 여부를 '국세청' 칸이 아니라 위하고에서 정하는 '유형'(카과 / 일반)으로
가른다(2026-11-23 통화). kafa 의 공제 기준을 유형으로 바꾸기 전에, 내려받은 파일의 유형
칸이 담당자가 고른 결과인지 자료로 확인한다.

```bash
python tools/check_type_vs_nts.py ~/kafa-out/_archive
```

유형 × 국세청 교차표와, 둘이 어긋나는 행이 처리 상태(계정 채워짐 / 비어 있음)별로 몇 건인지
보여 주고 읽는 법을 한 줄로 알려 준다. 마지막 '유형 추천 효과' 칸은 처리 전 행 중 같은 가맹점
이력으로 유형이 바뀌는 건수다(일반 → 카과 몇 건 등). 그 아래 두 칸은 처리된 행의 계정별
유형 분포와, 처리 전 행을 지금 도구로 분류했을 때의 계정별 공제 여부다 — 특히 '접대비로
추천됐는데 공제로 나가는 처리 전 행' 건수를 본다(접대비는 매입세액 불공제). 출력에는 수임처 이름이 없어 그대로 공유해도 된다.

## 직원 유무 조사표 만들기

```bash
kafa-clients template ~/수임처조사표.xlsx --from-db ~/kafa-out/kafa.db
```

이미 처리한 수임처 이름이 미리 채워진 엑셀이 나온다. 같은 이름의 파일이 이미 있으면 **덮어쓰지 않고
멈춘다**(담당자가 채운 내용을 지우지 않게). 정말 새로 만들려면 `--force` 를 붙인다.
`--from-db` 같은 경로가 없으면 빈 양식을 만들지 않고 멈춘다. 작성 방법 시트에 판단 기준
(아르바이트·일용직은 있음, 가족만은 수임처마다)이 있다.

담당자가 채워 오면 넣는다. 엑셀에서 옛 형식(.xls)으로 다시 저장해 와도 되고, '유/무'·'법'처럼
줄여 쓴 표기도 알아듣는다.

```bash
kafa-clients import ~/Downloads/수임처조사표.xls
```

- 저장 위치는 레포 **밖** `~/.kafa/clients.yaml` 이다(수임처 실명이 들어가므로 git 에 넣지 않는다).
  `kafa-run` 의 마스터 반영(개인/법인)도 같은 파일에 쓴다. 어느 폴더에서 실행해도 같은 파일이다.
- 기존 값(마스터에서 온 개인/법인, 기본값)은 지우지 않고 합친다. 처음 저장할 때는 예전에
  `config/clients.yaml` 에 적혀 있던 값을 이어받는다. 그 뒤로 `config/clients.yaml` 은 기본값만
  두면 된다(`git checkout config/clients.yaml` 로 되돌려도 된다).
- 화면에는 건수만 나온다(개인/법인, 직원 있음/없음/빈칸, 메모, 알아듣지 못한 표기의 행 번호,
  처리 이력과 이름이 맞는 곳, '(주)' 표기만 달라 이어 쓴 곳, 아직 직원 유무가 없는 곳). 그대로 공유해도 된다.
- 처리 이력의 폴더 이름과 조사표 이름이 '(주)'·'주식회사' 표기만 다르면 같은 수임처로 본다. 단, 그 폴더
  이름의 속성이 아예 없을 때만, 후보가 하나일 때만 그렇게 하고, '(주)' 폴더에 개인 속성은 붙이지 않는다.

## 미해소 행을 Claude 에게 묻기 (`kafa-ask`)

위하고도, 지난 처리 이력도 계정을 못 정한 행은 Claude 에게 묻는다. 질문지에는 **업태·종목·
품명·유형과 건수만** 들어간다(거래처·사업자번호·금액·날짜 없음). 붙여넣을 프롬프트와 판단
기준은 `docs/cowork_ask.md` 에 있다.

`kafa-run` 은 분류 직전에 물을 것을 정리한다. 새 질문이 있으면 **멈추고**(종료코드 3)
질문지 경로를 알려 준다. Claude 가 답지를 쓰면 `kafa-run --skip-fetch` 로 이어서 돌린다.
기다리지 않으려면 `--no-ask` 를 붙인다.

```bash
kafa-ask prepare     # 질문지 쓰기 → ~/kafa-out/_ai/questions.json
kafa-ask apply       # Claude 답지(answers.json) 검증·합치기 → picks.json (파이프라인도 자동으로 한다)
kafa-ask show        # 모인 답: 계정별 가짓수 · 모름 · 낮은 확신
kafa-ask exam        # 처리된 이력으로 시험지 만들기(정답은 로컬에만)
kafa-ask score       # 시험 채점 — 정답률, 확신 구간별 정답률, 틀린 예
kafa-ask prior       # 사무실 전체 이력 추천을 켜도 되는지 — 한 수임처씩 빼고 맞혀 본 정답률
```

`kafa-ask prior` 는 **다른 수임처들이 같은 업종을 처리한 계정**으로 추천하면 얼마나 맞는지 잰다
(기본 꺼짐). 기준별로 '채움 · 정답'(전체 / 처음 보는 가맹점)과 지금 미해소 중 채울 수 있는 건수가
나온다. 정답률이 Claude 시험의 '행 단위 · 적용되는 답' 정답률보다 높은 기준이 있으면 `config/rules.yaml` 의
`recommend.office_prior` 에 그 기준을 넣고 `enabled: true` 로 켠다. 켜면 순서는 수임처 이력 →
사무실 이력 → Claude 답이다.

- 이력·시드가 먼저고, Claude 답은 그것이 못 푼 행에만 쓴다. 확신 0.5 미만은 적용하지 않고
  리포트에 `AI(Claude) 메모` 로만 남긴다. 적용된 행은 '추천'(근거 `AI(Claude) 추정`,
  신뢰도 최대 70%)이라 검토 리포트의 추천내역에서 확인한다.
- **처음에는 `exam` → `score` 로 정답률부터 본다.** 확신 구간별 정답률로
  `config/rules.yaml` 의 `recommend.host_picks.min_confidence` 를 정한다.
- Claude(Cowork)에는 **`~/kafa-out/_ai` 폴더만** 연결한다. 그 안에는 질문지·답지뿐이고 시험 정답은
  `~/kafa-out/_exam/` 에 따로 있다. 명령은 사람이 Mac 터미널에서 돌린다.
- 첫 시험(2026-11-23): 확신 0.5 이상 답이 실제 계정과 **91%**(행 단위) 맞았다 → 기준 0.5 유지.
  식재료·부동산 임대는 모름으로.
- 사무실 전체 이력 추천은 실측 정답 76~79%·채움이 적어 꺼 둔다(2026-11-23).
- 모든 출력에 수임처·거래처 이름이 없어 그대로 공유해도 된다.
- 답을 처음부터 다시 받고 싶으면 `~/kafa-out/_ai/picks.json` 을 지운다.
